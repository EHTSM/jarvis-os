## THE MEASUREMENT DEFECT THAT INVALIDATED PART OF C.1

Before any code defect: **two server processes were bound to port 5050 for most of the C.1 audit.**

```
PID 6663   started Sunday 20:00   node /Users/ehtsm/jarvis-os/backend/server.js
PID 4107   started Thu 06:07      (child of PM2 God Daemon, 47 restarts)
```

`jarvis-os` runs under **PM2**. Every `pkill` I issued was answered by PM2 respawning the process, and a stale pre-session listener held the port. Requests were served by code that did not contain my edits — which is why the SPA fix appeared not to work, and why I initially reported "still masked" after a correct fix.

**Consequence for C.1's numbers:** the 51 reported timeouts and the 13.2 s `/collab/active` were measured under two competing processes on a single-threaded event loop. Corrected below.

**Lesson:** verify the *identity* of the process answering, not just that something answers. Restart via the process manager (`pm2 restart`), never `pkill`.

## DEFECT A — `GET /launch/onboarding/all` → 500 (100% of calls)

**Reproduced:** `{"error":"Cannot read properties of undefined (reading 'filter')"}`, 3/3 calls.

**Root cause — reader/writer divergence across two unrelated subsystems sharing one file:**

| Module | Writes to `data/onboarding-state.json` | Shape |
|---|---|---|
| `backend/services/onboardingEngine.cjs` | per-account onboarding | `{ [accountId]: { steps: [...] } }` |
| `agents/runtime/operatorOnboarding.cjs` | first-run operator flow | `{ completed: [...], operatorId, startedAt, finishedAt }` |

The live file contained **only the operator record**. `getAllProgress()` mapped over its values — `completed` (an array), `operatorId` (a string), two numbers — and called `s.steps.filter()` on entries that never had `.steps`.

**Minimal fix** — [onboardingEngine.cjs](backend/services/onboardingEngine.cjs): `_isAccountRecord()` shape guard, applied to `getAllProgress()`, `getProgress()` and `completeStep()` (all three had the same hazard). Storage paths untouched: the other module legitimately owns that file too, and repointing either would change its behaviour. No second onboarding model introduced.

**Verified — 8 states, none throwing:**

| State | Result |
|---|---|
| Live foreign operator record | `[]` |
| Empty store | `[]` |
| One valid record | `pct: 50` |
| Multiple valid records | both returned |
| Mixed valid + foreign | only the valid one |
| Malformed (`null`, string, `steps:[]`, `steps:"str"`, `[]`) | no throw; `pct: 0`, no divide-by-zero |
| `getProgress()` on foreign | `null` |
| `completeStep()` on foreign | `null` |

**Live re-verify:** `200 {"ok":true,"all":[]}` × 3.

## DEFECT B — `GET /computer/dashboard` → 500

**Reproduced** 3/3. **Exception isolated:**
```
r.command?.slice is not a function
  at computerExecutionEngine.cjs:422 (getStats)
  at getDashboard (computerExecutionEngine.cjs:427)
```

**Root cause — wrong TYPE, not null.** `execute(command)` persists whatever the caller passes. Of 500 stored runs, **109 hold an object** `{command, workspaceType}` instead of a string — and the **last 5 runs, the exact window `getStats()` reads, were all objects**. Optional chaining (`?.`) guards `null`/`undefined` but not a wrong type.

**Minimal fix** — `_commandLabel()` reader-side normalisation. Stored records untouched, writers unchanged; an object surfaces its inner `.command` instead of crashing.

**Live re-verify:** `200 {"ok":true,...}` × 3.

## DEFECT C — `GET /coding/smells` → 25–35 s

**Reproduced:** 34,838 / 28,766 / 25,948 ms; 1,481,426 bytes; warm ≈ cold (no caching).

**First hypothesis was WRONG.** I assumed repeated file I/O (11 detectors × 2,293 files ≈ 23,000 reads) and added a per-scan read memo. Result: **25,046 → 22,445 ms. Negligible.** File I/O was not the bottleneck.

**Profiled instead of guessing** — per-detector timing:

| Detector | Time | Smells |
|---|---:|---:|
| **`_detectDeadExport`** | **23,029 ms (92.5%)** | 692 |
| `_detectTodoFixme` | 778 ms | 11 |
| `_detectLongFunctions` | 209 ms | 538 |
| `_detectDuplicateLiterals` | 188 ms | 986 |
| all 9 others combined | < 550 ms | — |
| **TOTAL** | **24,882 ms** | 3,584 |

**Root cause:** `_detectDeadExport` ran `new RegExp("\\b"+name+"\\b").test(content)` for each candidate export against every other file. It short-circuits on the first match — so names that *are* used exit early, but the **693 genuinely dead exports each scanned the full 2,293-file corpus**: ~1.6M regex executions over whole file bodies.

**Minimal fix:** tokenise each file once into a `Set` of identifiers, then test membership. Identical whole-word semantics to `\bname\b` for identifier characters — a lookup-strategy change, not a rule change. Confidence (0.55) and false-positive profile unchanged.

**Result — 12x faster, byte-identical output:**

| | Before | After |
|---|---:|---:|
| Service scan | 24,919 ms | **2,018 ms** |
| Live endpoint (3 calls) | 34,838 / 28,766 / 25,948 ms | **3,178 / 2,298 / 2,392 ms** |
| Payload | 1,481,426 bytes | **1,481,426 bytes** |
| Smells | 3,582 | **3,582** |
| dead_export | 693 | **693** |

Payload size is unchanged deliberately: 1.48 MB is the feature's honest output for 3,582 real findings. Capping it would change the feature's purpose, which this phase forbids.

## DEFECT E — SPA catch-all masking (HIGH PRIORITY)

**Reproduced — only when AUTHENTICATED** (unauthenticated requests correctly 401):
```
GET /enterprise/orgs   → 200 + <!doctype html>
GET /dev/projects      → 200 + <!doctype html>
```

**Root cause:** `app.get("/*splat", _renderIndexHtml)` matches every unmatched GET, including API paths. The route barrel was already ordered correctly — the fallback simply cannot distinguish an API path from a frontend route.

**Minimal fix** — [server.js](backend/server.js): an API 404 boundary between the route barrel and the SPA fallback. The prefix list (150 entries) is **derived from the live router tree at boot**, not hardcoded, so it cannot drift as routes change.

**Verified:**

| Case | Before | After |
|---|---|---|
| `GET /enterprise/orgs` | 200 HTML | **404 JSON** |
| `GET /business/made-up` | 200 HTML | **404 JSON** |
| `GET /graph/nonexistent` | 200 HTML | **404 JSON** |
| `POST` to unknown API path | — | **404** (never 200 HTML) |
| `GET /graph/stats` (real) | 200 JSON | 200 JSON ✓ |
| `GET /` (frontend) | 200 HTML | 200 HTML ✓ |
| Unauthenticated `/graph/stats` | 401 JSON | 401 JSON ✓ |
| Tenant isolation | 12/12 denied | **12/12 denied** ✓ |

**Pre-existing, NOT caused by this fix:** `/reset-password`, `/verify-email`, `/accept-invite` return 401 rather than the SPA. Confirmed by stashing the change and retesting on baseline — identical 401. Not touched; out of scope for this phase.
