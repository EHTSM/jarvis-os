## P0 — Blocks real company operation (safety/security/data-integrity issues, or blocks every company regardless of niche)

1. **[FIXED — 2026-07-23, commit `b9efdba`] Confirmed cross-tenant IDOR in live CRM routes.** `backend/routes/business.js:301-331` (`POST /business/leads/qualify`, `PATCH /business/leads/:phone/stage`) calls `businessDataService.listLeads({limit:1000})` with no `orgId` argument, then mutates the found record with no org-membership check — any authenticated user of any org can read/modify another org's lead data. **Affects: every company using the CRM department (rows 1,9,21,24,31,34,37,40,52,61-70,95 and any company with CRM in the coverage matrix — effectively all 100).**
   **Fix:** all CRM data routes in `business.js` now require org membership (`requireOrgMember`) and always pass `req.org.id`; a second instance of the same pattern was found and fixed in `businessIntelligenceEngine.cjs`'s scan/health functions (reachable via `/business/intelligence/*`). Verified with real HTTP requests: cross-org read/update/delete/qualify all return 404; legitimate same-org access and unauthenticated rejection both still work correctly.

2. **[FIXED — 2026-07-23, commit `b8293bb`] No execution-layer approval gate on money movement.** Refunds execute immediately and unconditionally: `backend/routes/commercial.js:107`, `backend/routes/revenueOS.js:245` — neither references the real (and otherwise functional) `approvalEngine.cjs`/`approvalQueue.cjs`. Pricing changes, large purchases, contract signing, legal filing, tax filing/payment, live financial trading, and blockchain signing/transfers have **zero** enforcement anywhere in the codebase; template `governance.approvalRequired` fields are inert descriptive labels never consulted by executing code. **Affects: every company that transacts money — fintech, marketplace, e-commerce, subscription, healthcare-billing niches (rows 5,23,25,28,29,31,32,34,37,39,46,53,58,65,73,86,93,98) and, more broadly, any company at all once it processes a single refund or payout.**
   **Fix:** refund routes now enqueue via the existing `approvalQueue.cjs` and only execute once approved via the existing generic approve endpoint; new `wf_refund_credit`/`wf_refund_finance` policy entries added to `approvalPolicy.cjs`. Verified: pending → 202, execute-before-approval → 409, approve-then-execute → 200 (exactly once), re-execute → 409, cross-account execute → 403. **The other ~11 categories in this item (pricing, contracts, legal, tax, trading, blockchain) remain unenforced — no fake gates were added for actions that don't currently execute anywhere in the codebase.**

3. **[FIXED — 2026-07-23, commit `ee6a446`] Company creation never actually executes agents.** `companyFactory.cjs:199` and `companyWorkspaceBuilder.cjs:129` hardcode `dryRun: true` when assigning a workforce — the real AI-provider execution path (`autonomousExecutionEngine.executeWorkflow`) is never invoked as part of company creation. Every "company" created through the factory is a structured set of JSON records, not a running autonomous operation. **Affects: all 100 companies — this alone caps every row in the coverage matrix below "READY NOW."**
   **Fix:** both call sites now run with `dryRun:false`; verified company-creation mission titles never match the workflow-inference patterns that would trigger a gated `executeWorkflow` run, so real execution safely falls to the existing bounded engorg-dispatch simulation. Also added an honest `NEEDS_CREDENTIALS` connector-readiness report to the creation pipeline (no connector is auto-attached — none can be without real credentials). Verified via real HTTP: a freshly created company's timeline shows a real `dispatched` execution outcome.

4. **No RBAC/permission assignment step exists in the company factory.** `companyLifecycleEngine.cjs:141` — verbatim comment: "No parallel company-scoped storage or permission system is created here." A newly created company has no permission model until someone manually configures one. **Affects: all 100 companies.**
   **Status: re-confirmed accurate, not fixed.** This is honestly represented as absent, not fabricated as present — the org's `org_owner` role (assigned to the creator at org-creation time, which is real) is the correct and complete RBAC state for a freshly created single-owner company; building out a fuller per-company RBAC model would be new capability work, out of scope for this remediation pass.

5. **Single-process, non-cluster-safe architecture, hard-pinned.** `ecosystem.config.cjs:33-35` sets `instances: 1` with an explicit comment that in-process singletons (taskQueue, learningSystem, contextEngine) "are NOT cluster-safe. Never set instances > 1." Combined with flat-JSON whole-file read/write on every operation and non-atomic writes in most services (`organizationService.cjs` and others), this is a structural ceiling, not a configuration knob. **Affects: any deployment beyond a handful of concurrent orgs — blocks the "100 companies" goal at the infrastructure level, independent of any single company's niche.**
   **Status: not fixed — explicitly out of scope.** This is an architectural/infrastructure change (process model, storage engine), not a targeted bug fix; no remediation was attempted here per the mission's scope.

6. **[FIXED — 2026-07-23, commit `5899682`] Fake health checks silently report connectors as working when they are not verified.** `auth:github`, `auth:apple`, `auth:discord` (OAuth) and `auto:zapier` report `CONNECTED` without making any real network call (`integrationConnectors.cjs:816-817, 859-860, 867-868, 1108`). An operator trusting the dashboard would believe these integrations work when they have never been tested. **Affects: any company relying on Zapier automation or Apple/Discord/GitHub OAuth login as a trust signal.**
   **Fix:** Apple now probes a real OIDC discovery endpoint; Discord now probes its authorize endpoint (empirically confirmed to genuinely discriminate valid vs. malformed client_id — HTTP 302 vs. 400); Zapier now does a real reachability probe of the catch-hook path (HTTP 200 vs. 404 for malformed paths); GitHub OAuth has no unauthenticated endpoint capable of discriminating a real client_id from a fake one, so it now honestly reports `PARTIAL` instead of a fabricated `CONNECTED`. Verified with real env vars set/unset against the real connector functions. **`infra:firebase`'s JSON-parse-only check and `email:ses`'s by-design no-probe limitation (2 separate, narrower findings) were explicitly left unfixed per the approved scope.**

   **Also found and fixed during remediation, not in the original P0 list:** production deployment's `requireApproval:true` floor (`deploymentCoordinator.cjs`) could be silently overridden to `false` via `POST /deployment/run`'s request body, defeating the one execution-layer approval gate the original audit found (commit `c0d8dca`). Now a floor a caller can raise but never lower; verified via real HTTP that a production deploy request with `requireApproval:false` in the body still enforces the gate.

## P1 — Required for broad 100-company coverage (missing reusable capability blocking many companies at once)

7. **No dynamic/new skill creation pipeline exists at all.** No `eval`/`new Function`/generated-file-`require()` pipeline for creating genuinely new executable agent skills was found anywhere. All "composition" is selection among a fixed, static set. **Affects: any company whose niche needs a capability outside the current fixed set — a large fraction of the 100-company target, since the entire premise of covering 100 diverse niches from ~90 reusable skills depends on being able to add the missing ones without a full engineering project each time.**

8. **[PARTIALLY FIXED — 2026-07-23, commit `46b86e1`] ~41 real agent-logic files are completely unreachable from the running server.** `agents/business/*`, `agents/content/*`, `agents/internet/*`, `agents/multi/*`, `agents/system/*` (SEO, social media, content/copywriting, image/video/voice generation, market intelligence, competitor tracking, web research) have working per-file logic but zero `require()` from anywhere under `backend/`. This is the single highest-leverage fix available: wiring these in requires no new development, only connecting existing code. **Affects: every marketing/content/creative/research-heavy niche — rows 6,11,13,14,16,17,18,25,26,37,44,55,59,60,81,82,84,85,89 and more.**
   **Fix (partial):** all 41 files were individually `require()`-tested (not assumed from barrels). 15 of 35 non-`agents/multi` files are actually **BROKEN** (fail to even load — 7 reference nonexistent `agents/crm.cjs`/`agents/paymentAgent.cjs`, 8 reference nonexistent `agents/core/groqClient.cjs`), which is the real reason `business/index.cjs` and `content/index.cjs` — the only files that ever required them — also throw at require-time. `agents/multi/*` (6 files) is a duplicate parallel registry and was correctly left alone. The 13 remaining files that loaded cleanly and matched the real registry's `run(task)` contract (analytics, revenue, subscription, content scheduler, voice cloning, and all 10 internet research/intelligence agents) are now registered in `agents/runtime/agentRegistry.cjs` via `bootstrapRuntime.cjs`, with matching `taskRouter.cjs` entries. Verified via the real dispatch path including a live third-party network call. **The 15 BROKEN files and the missing `agents/crm.cjs`/`agents/paymentAgent.cjs`/`agents/core/groqClient.cjs` dependencies remain unfixed — repairing them would be new development (recreating missing modules or rewriting the broken agents' logic), not recovery of existing working code, and is out of scope for this remediation pass.**

9. **14 of 32 department families have zero code of any kind:** HR/Recruitment, Legal/Compliance, Procurement, Supply Chain, Inventory/Warehouse, Logistics, Manufacturing/Production, IoT/Robotics/Maintenance/Quality, Energy/Infrastructure, Video/Audio/Media production (as a department, not just an AI capability tag), 3D/CAD (same), Support/ticketing, Administration, Simulation/Digital Twin, Blockchain/Web3. **Affects: rows 3,7,8,19,22,23,27,30,32,33,36,38,39,41-50 (nearly all of Healthcare and ERP templates),64,66,68,71-80 (nearly all of ERP template),86,87,90,92,96,97,98 — roughly 40-45 of the 100 illustrative rows are blocked by one or more of these missing families.**

10. **Connector coverage is limited to 13 phases (A–M); entire vendor categories are absent:** external CRM (Salesforce/HubSpot), support/helpdesk (Zendesk/Intercom), accounting (QuickBooks/Xero), shipping/logistics (Shippo/EasyPost), maps/geospatial (Google Maps referenced but explicitly "not referenced in current codebase" per `pcs2ExternalPlatforms.cjs:347`), video/audio platforms, 3D/CAD tools, mobile-distribution and desktop-signing APIs, IoT platforms, blockchain/Web3, market/trading data feeds, scientific/deep-tech systems. **Affects: e-commerce/logistics niches (22,23,27,30,36,72,77), field-sales/geospatial (66,77), video/audio products (13,59,84,85), 3D/CAD (19,44,87), trading (86,39), and any specialized/regulated niche.**

11. **Memory/knowledge isolation is opt-in per call site, not enforced by the store.** `memoryPersistenceLayer.cjs` (the actual memory agents recall from at runtime) has no orgId/companyId concept at all; `businessDataService.cjs:47-58` explicitly documents that omitting orgId anywhere makes every record globally visible/writable. `orgKnowledgeGraph.cjs:167-177` `getOrgImpact()` has a code comment describing an isolation filter that the function body never actually implements — a second, distinct cross-org data leak beyond the P0 IDOR. **Affects: all 100 companies' data confidentiality, worst for companies handling sensitive data (healthcare rows 41-50, finance rows 5,39,86).**

12. **Organization-boundary middleware is broken by default for `:orgId`-param routes** and has already required multiple hand-patches. `orgMiddleware.cjs`'s `attachOrg` never reads `req.params.orgId` — naive composition on any `:orgId`-param route silently authorizes against the wrong org. Several route files (`enterpriseDashboard.js`, `enterpriseMonitoring.js`, `orgAiBrain.js`, `orgAgents.js`, `crossOrgCollaboration.js`) explicitly document this bug in their own comments and claim to have manually patched around it — meaning the underlying trap remains for any future route author. **Affects: all 100 companies, and specifically any future engineering work extending org-scoped routes.**

13. **Company factory has no niche-classification beyond a 10-keyword regex ladder over 10 static templates**, defaulting to `saas` when nothing matches (`businessTemplateEngine.cjs:172-191`). This is far short of composing "any of 100 niches" — it can only ever select among 10 predefined shapes. **Affects: all 100 companies' initial setup fidelity.**

14. **Company-level connector attachment is entirely absent from the automated creation pipeline** — connectors must be manually wired per company after the fact via the founder-facing proxy routes; there is no step 5 ("attach appropriate connectors") in the actual factory code. **Affects: all 100 companies.**

15. **Production deployment is the only execution-layer approval gate in the entire system, and it defaults to off.** `deploymentCoordinator.cjs:205` — `requireApproval` defaults to `false` unless explicitly requested; and the "deploy" action itself is simulated (comment at line 432-434: "In a real system this would shell out to npm/docker/kubectl... Here we call the existing build_run capability"). **Affects: rows 4,15,83,91,100 and any engineering-heavy niche relying on this as a safety mechanism.**

## P2 — Specialized niche capability (affects a narrower subset)

16. **No compliance/legal-workflow agent or service exists anywhere.** Blocks healthcare (41-50), finance/lending (5,39), legal-document niches (7,33,48,62,97), and any regulated vertical's governance requirement, even though templates declare governance fields for these industries.

17. **No medical/clinical decision-support infrastructure of any kind** — not just missing an approval gate (P0 #2 covers enforcement), but no domain logic, no clinical-safety guardrails on the generic AI capability. Blocks rows 41,45,46,48,49,50,80 entirely (Requires Specialized External Infrastructure or Not Supported).

18. **No trading/market-data connector and no live-financial-trading safeguard** beyond the generic (unwired) market-intelligence agent. Blocks row 86 and any quant/trading niche.

19. **No geospatial/mapping capability** (Google Maps referenced in one file but explicitly annotated as unused). Blocks field-sales (66), logistics/fleet (77), delivery/perishables (27) niches.

20. **3D/CAD and Manufacturing/IoT/Robotics/Energy families are entirely absent** beyond a regex-based AI capability-routing tag (`capabilityRouter.cjs:27-28`) that has no actual business logic behind it. Blocks rows 19,71,75,76,87,90 and similar physical/industrial niches — these categories require external specialized infrastructure this project has never integrated with.

21. **Cross-company intelligence is two hardcoded heuristics**, not a general system (`companyFactory.js:91-109`: stage-bottleneck count, risk-score threshold). Limits any portfolio-level insight product (row 69, franchise/multi-brand niches) to superficial signals.

## P3 — Optional enhancement

22. **"Load-test verified" claims in project memory/docs are not backed by any test in the repository.** The largest real concurrency test found is 20 concurrent HTTP requests (`tests/stress/01-http-stress.test.cjs`); other "stress" files are sequential in-process loops of 20-30 iterations. This doesn't block any single company's operation today but means every scale claim beyond "1 company, lightly used" is unverified and should not be relied upon for capacity planning.

23. **Duplicate/redundant connector-probe code.** `pcs2ExternalPlatforms.cjs` independently re-implements several of the same probes already in `integrationConnectors.cjs` (Google Drive/YouTube/Calendar/Slack/Figma) — not a functional gap, but a maintenance/consistency risk (two places to update credentials logic).

24. **Enterprise CRM frontend surface is a pure client-side mock.** `frontend/src/.../EnterpriseCRM.jsx` reads only `localStorage` and ships hardcoded seed data (`SEED_OPPS`/`SEED_TEAM`) with zero backend fetch, despite presenting as a live CRM pipeline — distinct from the separately-wired, real `ContactsV2.jsx`/`crmApi.js` surface. Cosmetic/trust issue, not a functional blocker, since a real CRM surface exists elsewhere in the app.
