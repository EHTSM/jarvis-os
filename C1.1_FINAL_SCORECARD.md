## Documented false positives — preserved, not erased

### From C.1
1. **3 tenant leaks** — status-code-only checking against nonexistent paths; the SPA catch-all returned 200 HTML to the owner too. *Lesson: inspect the body, never the status alone.*
2. **5 orphaned services** — regex matched only `require("../services/x")`, missing `require("./x.cjs")`. *Lesson: never rely on one pattern for reference analysis.*
3. **3 broken frontend chains** — POST-only routes probed with GET. *Lesson: match the probe method to the route definition.*

### From C.1.1
4. **51 timeouts / 13.2 s `/collab/active`** — two server processes competing for port 5050 (stale listener + PM2 respawn). *Lesson: verify which process answers; restart via the process manager.*
5. **"752 real-data endpoints"** — classifier counted non-empty strings as data. True figure: **416**. *Lesson: one classifier, applied identically to every run.*
6. **WhatsApp/Telegram "missing credentials"** — probed invented variable names. Both provisioned as `WA_TOKEN` / `TELEGRAM_TOKEN`. *Lesson: check the name the code reads.*

A seventh near-miss, caught before publication: I hypothesised file I/O as the `/coding/smells` bottleneck and implemented a read cache that yielded only 25.0 s → 22.4 s. Profiling then showed `_detectDeadExport` was 92.5% of runtime. **Profile before optimising.**
