# A.11.2 — R2: Dashboard Overflow

**Result: OPEN — reproduced and attributed, two recovery attempts failed and
were reverted. Not claimed fixed.**

---

## Reproduction (live, authenticated)

| Viewport | Dashboard | Other surfaces |
|---:|---:|---:|
| 1440 / 1280 / 1024 / 768 | 0px | 0px |
| 430 | **35px** | 0px |
| 390 | **75px** | 18px |

`document.scrollWidth 465` against `clientWidth 390`.

---

## Attribution (DOM probe, not CSS inspection)

`scripts/a111-overflow-probe.cjs` asked the DOM which elements exceed the
viewport:

```
w=105 right=434  div.cmd-root > div.cmd-quick-actions > button.cmd-qa-btn
w= 95 right=611  div.cmd-root > div.cmd-quick-actions > button.cmd-qa-btn
w= 95 right=548  section.cmd-panel.cmd-col-dispatch > div.cmd-dispatch-chips > button.cmd-chip
```

Both rows already declare `overflow-x: auto` and are *designed* to scroll.

---

## Recovery attempts — both failed, both reverted

| # | Hypothesis | Change | Measured result |
|---|---|---|---|
| 1 | the scrollable rows can't shrink | `min-width: 0` + `flex-shrink: 0` on `.cmd-quick-actions` / `.cmd-dispatch-chips` children | **unchanged** (465px) |
| 2 | the grid item can't shrink | `min-width: 0` on `.cmd-layout`, `.cmd-layout > *`, `.cmd-panel` | **unchanged** (465px) |
| 3 | the flex container can't shrink | `min-width: 0` on `.cmd-root`, `.cmd-root > *` | **unchanged** (465px) |

**All three were reverted.** Leaving CSS that does not move the measurement
would be dead code asserting a fix that did not happen.

---

## What this means

The constraint is **not** where the CSS cascade suggests. Three plausible
ancestors were eliminated by measurement. The next step is to walk the
Dashboard's computed flex/grid chain live — reading each ancestor's
`min-width`, `flex-basis` and `width` at 390px until the element that refuses to
shrink is identified by evidence rather than hypothesis.

That was not completed within this phase.
