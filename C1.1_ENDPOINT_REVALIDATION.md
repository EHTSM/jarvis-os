## CORRECTION — the C.1 "752 real-data" figure was wrong

C.1 reported **752 REAL+WORKING**. That number came from a classifier that treated **any non-empty string at any depth** as evidence of data — so a response carrying only a label, an id, or a `generatedAt` timestamp counted as "working" while every array was empty and every number zero.

A single canonical classifier has now been applied to **both** runs. "Data" requires at least one **non-empty array** or **non-zero number** below the response envelope; bare strings do not qualify, because they are present even on a completely empty tenant.

| | 200s | real-data | empty-state |
|---|---:|---:|---:|
| **C.1 (reclassified)** | 915 | **416** | 499 |
| **C.1.1** | 919 | **435** | 484 |
| delta | +4 | **+19** | −15 |

**The honest figure for C.1 was 416, not 752.** No endpoint regressed from data to empty (verified: 0 flipped). The +19 improvement is genuine — it comes from the three fixed 500s plus endpoints that previously timed out.

C.1's headline claim that "a 200 overstates capability by ~18%" was directionally right but understated. The true ratio: **435 of 919 200-responses (47%) carry real data**; the other 53% are structurally valid but empty.
